# Using Generative AI Tools - Boon or Bane

## Project Overview

This repository contains the organised research materials for the study
"Using Generative AI Tools - Boon or Bane." The project investigates the
benefits, risks, and user experiences associated with generative AI tools.

## Repository Structure

- `01_literature_review/`: Journal articles, conference articles, books,
  newspaper articles, and reference information.
- `02_quantitative_analysis/`: Survey questions, de-identified survey data,
  analysis scripts, results, and the survey analysis report.
- `03_qualitative_analysis/`: Interview protocols, consent form templates,
  anonymised transcripts, thematic analysis, insights, and visualisations.
- `04_drafts_and_reports/`: Research proposals, conference paper drafts,
  and final reports.
- `05_additional_materials/`: Information sheets, approved photos, and
  other media files.
- `06_documentation/`: Data dictionaries, file-naming instructions,
  the project logbook, and data management documentation.

## How to Navigate the Repository

Start with this README file to understand the project. Use the numbered
folders in order. Raw or source materials are stored separately from
processed data, analysis scripts, results, and reports.

## Data Access and Security

Only de-identified, anonymised, or fictional class data should be stored
in this repository. Signed consent forms, interview recordings,
identifiable transcripts, and identifiable survey responses must be
stored in an approved restricted-access system such as UQRDM. Team
members must not upload personal information, passwords, access tokens,
or other confidential information to GitHub.

## File-Naming Convention

Files should use clear and consistent names. Dates should use the
`YYYYMMDD` format, version numbers should use `v01`, `v02`, and so on,
and underscores should separate major elements.

Example:

`20260915_GenAI_SurveyData_Deidentified_v01.csv`

Avoid spaces, special characters, and unclear terms such as
`final_final_new`.

## Version Control

Each meaningful change should be committed separately. Commit messages
should clearly explain the change, for example:

- `Add de-identified survey data`
- `Add initial quantitative analysis script`
- `Update interview coding categories`
- `Revise draft research report`

## Contribution Guidelines

1. Fetch and pull the latest version of the main branch.
2. Create a new branch with a clear name.
3. Make and review the required changes.
4. Commit the changes using a meaningful message.
5. Push the branch to GitHub.
6. Create a pull request to the main repository.
7. Explain the purpose of the change in the pull request.
8. Wait for the code reviewer to review and merge the change.
9. Resolve any merge conflicts before completing the merge.

## Documentation and Reproducibility

Analysis scripts should contain comments explaining their purpose and
required inputs. Processed datasets should be accompanied by a data
dictionary. Important analytical decisions and changes should be
recorded in the project logbook.
